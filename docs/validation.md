تشمل الفحوص العملية: اشتراط الموافقة، ورفض الطلبات من مصدر مختلف، وحماية بيانات غير المسجلين، والاختبار القبلي، وعدم تسريب مفتاح الإجابة حتى عند إعادة الطلب، ومنع بدء جلسات تدريب مكررة بالتزامن، والإجابة الخاطئة ثم التلميح وإعادة المحاولة، وحفظ التقدم بعد تحديث الصفحة، وعزل بيانات المشاركين، والحفاظ على درجة المحاولة الأولى، وأهلية اليوم الرابع عشر، وإدارة المحتوى والتصدير، واشتراط اعتماد بشري، وعرض الجوال، وحذف الحساب.

اختبارات موصل النموذج الثلاثة تستخدم استجابات محاكاة للتحقق من العقد البرمجي فقط، ولا تثبت نجاح الاتصال الحي أو جودة التلميحات.

نُظفت بيانات المشاركين التي أنشأتها الفحوص. بعد التحقق: 0 مشاركين، و0 أسئلة معتمدة، و0 دفعات. لا توجد إحصاءات نجاح مزروعة.

حُفظت إعدادات `install_script` و`start_skill` في مسودة البيئة، إضافة إلى متطلب `PRAXIS_AI_API_KEY` ومتغير النموذج واتصال `api.openai.com`. حفظ المسودة لا ينشر النظام ولا يضيف قيمة للمفتاح. رفع المصدر إلى GitHub، وتطبيق إعدادات Railway، ونجاح النشر مراحل منفصلة؛ وجود الفرع وحده لا يثبت أن الموقع يعمل على الاستضافة.

حُفظ أيضًا متطلب رمز مشروع `RAILWAY_TOKEN` لوجهة `backboard.railway.com` ونطاقات Railway المطلوبة. لم يُضف رمز فعلي، ولم يُنشأ مشروع أو مورد مدفوع أو نطاق. أداة Railway 5.63.1 مثبتة، وفحص حالتها أكد غياب المصادقة. كانت شبكة الجهاز الحالي ترفض الاتصال بـ API قبل تطبيق تغييرات الإعدادات. [تفاصيل تجهيز النشر](railway.md).

خلال فحص المعاينة الأول استخدم عميل HTTP الاختباري ملفات ارتباط آمنة عبر HTTP محلي، فرفض إرسالها. صُحح الفحص ليستخدم `fetch` من المتصفح نفسه، كما يفعل التطبيق، ثم نجحت الفحوص الخمسة. حُذف مشارك الفحص الأول أيضًا؛ لم تُخفّف حماية ملفات الارتباط ولم يُعطّل التحقق من TLS.
