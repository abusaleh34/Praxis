# معاينة Praxis على Railway

هذه نسخة معاينة خاصة للمراجعة، وليست إطلاق تجربة الطلاب. تبقى الأسئلة مسودات، والتلميحات مرجعية بلا اتصال مدفوع بالنموذج. إعداد المعاينة لا يفعّل الدفع أو التسويق.

## ما تم تجهيزه

- `.railway/railway.ts` يصف خادم `praxis-preview` وقاعدة `Postgres` مستقلة. لا يربط النشر بفرع GitHub لم يُرفع بعد؛ يُرفع المصدر مباشرة بأداة Railway.
- Railway SDK مثبت على `3.12.0`. أداة Railway المثبتة في بيئة العمل: `/workspace/tools/railway-bin/railway`، إصدار `5.63.1`.
- البناء: `npm run build`. قبل النشر: فحص الإعدادات ثم `npm run db:migrate`. التشغيل: `npm run start:preview`، على `0.0.0.0` ومنفذ `PORT` الذي توفره الاستضافة.
- فحص الجاهزية `/api/health` يختبر اتصال PostgreSQL فعليًا. لا يكشف بيانات المستخدمين.
- الصفحات تحول الزائر إلى صفحة دخول داخل الموقع في `/preview`، بكلمة المرور من `PRAXIS_PREVIEW_PASSWORD`. الدخول ينشئ ملف ارتباط موقّعًا وآمنًا لمدة 7 أيام؛ تغيير كلمة المرور يبطل الجلسات القديمة. تبقى الواجهات والملفات الثابتة محمية، وجلسة الطالب منفصلة عن بوابة المعاينة. لا يتطلب الدخول نافذة مصادقة خاصة بالمتصفح. تستمر بيانات HTTP Basic القديمة بالعمل للتوافق.
- يتوقف التشغيل إذا نقص اتصال قاعدة البيانات أو أسرار الدخول أو إعداد ملفات الارتباط الآمنة. يتوقف أيضًا إذا تغير الوضع إلى إطلاق عام أو فُعّل رابط الدفع.
- لا توجد أسرار في ملف النشر. ملفات `.env*` الخاصة مستبعدة من Git ومن حزمة التسليم.

## الخطوة المطلوبة من صاحب الحساب

1. ادخل [Railway](https://railway.com) وأنشئ مشروعًا فارغًا مخصصًا لمعاينة Praxis. لا تستخدم مشروعًا يحوي خدمات أخرى، لأن ملف IaC يصف المشروع كاملًا.
2. من إعدادات المشروع أنشئ **Project Token** للبيئة المقصودة. احفظه باسم `RAILWAY_TOKEN` في إعدادات أسرار بيئة Codex؛ لا ترسله في المحادثة. لا يحتاج هذا المسار رمزًا بصلاحية حسابك كاملًا.
3. احفظ إعدادات شبكة بيئة Codex التي أضيفت لها `backboard.railway.com` و`railway.com` و`docs.railway.com`. حفظ المسودة وحده لا يثبت تطبيق سياسة الشبكة في الجهاز الحالي.

بعد توفر الرمز ووصول الشبكة يمكن للوكيل تنفيذ الباقي: فحص المشروع المحدد بالرمز، تجهيز أسرار المعاينة، تطبيق الإعدادات، رفع المصدر، والتحقق من رابط HTTPS. لا تفترض أن إعداد الرمز أنشأ موقعًا أو قاعدة بيانات.

## إجراء النشر

إذا أُنشئت بالفعل خدمة `Praxis` من GitHub، كما في لقطة المستخدم بتاريخ 4 أكتوبر 2026، فحافظ على هذه الخدمة. مشروع اللقطة اسمه `handsome-acceptance` وبيئته `production`، وكانت الخدمة تشير إلى فرع `main` غير موجود بعد. إنشاء الفرع ورفع المصدر يعالج رسالة الفرع؛ لا يجهز قاعدة البيانات أو الأسرار تلقائيًا.

لا تطبّق ملف IaC الخاص بالمشروع الفارغ على هذه الحالة مباشرة. بعد توفر اتصال الحساب، افحص الخدمات والتغييرات المعلقة أولًا، ثم طابق إعدادات خدمة `Praxis` مع أوامر البناء والتشغيل والجاهزية أعلاه وأضف قاعدة البيانات المطلوبة دون حذف الخدمة القائمة. اسم بيئة Railway `production` لا يغيّر شرط `PRAXIS_MODE=development` للمعاينة.

من جذر المشروع، بعد المصادقة وتحديد المشروع/البيئة:

1. تحقق من أن البيئة فارغة ومخصصة لهذه المعاينة. لا تستخدم `--confirm-destructive` لتجاوز حذف غير متوقع.
2. أنشئ متغيرين مشتركين داخل بيئة Railway: `PRAXIS_ADMIN_TOKEN` عشوائيًا بطول 32 حرفًا على الأقل، و`PRAXIS_PREVIEW_PASSWORD` عشوائيًا بطول 24 حرفًا على الأقل. لا تنسخ أسرار قاعدة التطوير إلى الاستضافة. لا تطبع القيم في السجلات أو تحفظها في المصدر.
3. شغّل `railway config plan`، وافحص أنه يضيف خدمة الويب وقاعدة البيانات فقط. الأمر يحتاج حسابًا وشبكة، ولم يُختبر بعد ضد حساب Railway.
4. شغّل `railway config apply --yes` لتطبيق الخطة المراجعة، ثم `railway up --service praxis-preview --detach`. يحترم الرفع `.gitignore`؛ لا تستخدم `--no-gitignore`.
5. تابع حالة النشر حتى تنجح التهيئة والبناء والهجرة وفحص الجاهزية. إذا فشلت، اقرأ السبب قبل إعادة المحاولة؛ لا تمسح قاعدة البيانات.
6. أنشئ نطاق Railway للخدمة بـ `railway domain --service praxis-preview`، واستخدم رابط HTTPS الذي تعيده الخدمة فعليًا. لا تُنشئ أو تخمّن رابطًا.
7. افحص أن فتح الصفحة بدون كلمة المرور يحول إلى صفحة الدخول، وأن الواجهات المحمية ترجع 401 وفحص الجاهزية يرجع 200، ثم جرّب الدخول والتسجيل والاختبار والتلميح من المتصفح. لا تستخدم اختبارات توليد البيانات المحلية ضد طلاب حقيقيين.

Railway يحدد تكلفة التشغيل حسب الحساب والموارد؛ لا توجد هنا مطالبة بمجانية الاستضافة أو تفعيل اشتراك مدفوع. تُراجع الحدود والتكلفة الفعلية في الحساب قبل إنشاء الموارد إذا تطلبت ترقية أو التزامًا جديدًا.

## الاختبار المحلي

```sh
npm test
npm run build
# قيم المعاينة محفوظة محليًا في .env.preview وغير متتبعة:
node --env-file=.env.local --env-file=.env.preview scripts/start-preview.mjs
# في جلسة أخرى؛ الفحص مقيد بعناوين loopback ويحذف مشاركه التجريبي:
node --env-file=.env.local --env-file=.env.preview scripts/check-preview.mjs
```

الخادم المحلي اختُبر مع PostgreSQL 17. مساعد PostgreSQL في Railway SDK الحالي يختار قالب PostgreSQL 18؛ نشر هذا القالب وهجرة المخطط عليه يحتاجان فحصًا فعليًا عند الربط. لا يُعد نجاح الاختبار المحلي تحققًا من خوادم Railway.
