# Praxis — الفكرة أولًا

تجربة عربية لتدريب طلاب القدرات على الهندسة: اختبار قبلي، جلسات من خمسة أسئلة مع رسوم وتلميحات، ثم اختبار بعدي بعد 14 يومًا. هذه **نسخة تطوير داخلية**؛ المحتوى مسوّد ولم يعتمده معلم، ولم يُقَس أداء نموذج لغوي بعد.

## التشغيل

المتطلبات: Node.js 24، npm، Docker مع Compose. قاعدة البيانات PostgreSQL 17، وصورتها مثبتة بالبصمة.

```sh
npm ci
npm run setup:local
npm run dev
```

`setup:local` ينشئ إعدادات خاصة في `.env.local` و`.env.db` مرة واحدة، ويشغّل PostgreSQL على المنفذ المحلي 55432 ويطبّق مخطط البيانات دون مسحها. إذا كانت الإعدادات موجودة يحافظ عليها. لا تضف هذه الملفات إلى Git. في بيئة Codex يمكن ضبط `npm_config_cache=/workspace/.npm-cache` عند تعذر الكتابة إلى مخبأ npm الافتراضي.

- `/`: تعريف بالتجربة.
- `/start`: الدخول والموافقة.
- `/learn`: مساحة الطالب.
- `/library`: ثماني مهارات هندسية.
- `/session/[id]`: جلسة اختبار أو تدريب.
- `/progress`: التقدم والحذف الاختياري للبيانات.
- `/admin`: إدارة القياس ومراجعة المحتوى؛ الرمز في `PRAXIS_ADMIN_TOKEN` داخل الإعدادات الخاصة.
- `/privacy`: سياسة نسخة التطوير وحدودها الحالية.

## التحقق

لنشر نسخة معاينة خاصة قابلة للتفاعل على Railway، راجع [دليل النشر](docs/railway.md). إعداداتها جاهزة في `.railway/railway.ts`؛ النشر الفعلي يتطلب ربط الحساب وتطبيق الإعدادات ورفع المصدر.

```sh
npm test
npm run typecheck
npm run build
# مع خادم تطوير يعمل وقاعدة البيانات المحلية:
npm run test:e2e
npm run quality:authored
```

اختبارات المتصفح تستخدم Chromium؛ يوجد في بيئة Codex في `/usr/bin/chromium`. للبيئات الأخرى ثبّت متصفح Playwright أو اضبط `PLAYWRIGHT_EXECUTABLE_PATH`. بيانات المشاركين التي تنشئها اختبارات الرحلة تُحذف عند انتهائها. صور التحقق داخل `test-results/` محلية وغير متتبعة.

## المحتوى والقياس

- `content/questions.json`: 80 مسودة أصلية: 50 تدريب + 15 قبلي + 15 بعدي.
- `content/evaluation-cases.json`: 150 إجابة خاطئة لاختبار التلميحات، ثلاث لكل سؤال تدريب.
- ثمانية قوالب SVG: المثلث، متساوي الساقين، المتوازيات، الزاوية الخارجية، المستطيل، المثلث القائم، الدائرة، المضلع المنتظم.
- صحة الإجابات يحسمها الخادم من المرجع. مفاتيح الاختبارين وحلولهما لا تُرسل للمتصفح.
- يعاد توجيه المحاولة الخاطئة بتلميحات. تبقى نتيجة التدريب مبنية على **المحاولة الأولى** حتى لو صُححت الإجابة لاحقًا.
- النتائج المعروضة حقيقية من قاعدة البيانات؛ لا توجد نتائج تسويقية مزروعة.

الأصلية هنا تعني أنها أُنشئت لهذا المشروع ولم تُنقل من تجميعات. لا يعني ذلك اعتماد صحتها التعليمية أو تكافؤ صعوبة الاختبارين؛ تلك مراجعة بشرية لازمة.

## ربط النموذج

اضبط `PRAXIS_AI_API_KEY` و`PRAXIS_AI_MODEL` في إعدادات آمنة. الاستدعاءات من الخادم فقط إلى `api.openai.com` باستخدام واجهة Chat Completions بمخرجات JSON محددة. التلميحات المرجعية تعمل دون مفتاح، وتستخدم عند تعطل النموذج أو بلوغ الحد اليومي. لا يظهر المفتاح أو نصوص الاستدعاءات في السجلات.

```sh
# افتراضيًا 5 حالات، ولكل حالة 3 تلميحات؛ هذا ينفق من حساب المزود.
npm run quality:ai
# الاختبار الكامل 150 حالة = حتى 450 استدعاء؛ لا تشغّله دون ميزانية محددة.
PRAXIS_EVAL_CASE_LIMIT=150 npm run quality:ai
```

التقارير الأولية تحمل `accuracy: null` حتى يصححها المراجع. نجاح الاختبارات البرمجية ليس إثباتًا لجودة النموذج أو بلوغ 95%.

## أوضاع التجربة

- `development`: تجربة داخلية للمطور، مع توضيح أن المحتوى مسوّد.
- `waitlist`: تسجيل اهتمام فقط، بلا تدريب. يتطلب مراجعة الخصوصية. يمكن إضافة قناة مملوكة عبر `PRAXIS_TELEGRAM_CHANNEL_URL`.
- `pilot`: تجربة مغلقة، تتطلب مراجعة المحتوى الكامل ورمز دخول وHTTPS وأعلام جاهزية الطلب والخصوصية والتلميحات. تُعزل هويات الأوضاع عن بعضها.
